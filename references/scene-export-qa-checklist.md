# 场景导出成品质检清单

适用范围
- 重点人工质检场景：`01 / 04 / 05 / 08 / 17 / 18 / 19`
- 目标产物：`DOCX / XLSX`
- 目标标准：更接近平台项目卡 / 平台报告，而不是本地脚本导出感

## 通用验收

1. 标题与封面
- 标题是否为中文项目名 + 中文场景名，而不是旧的 `Scene XX Report`
- 封面是否包含清晰的交付类型、状态、工作流标识、章节数
- 封面指标卡是否一眼可读，没有英文残留或字段错位

2. 中文化
- 结构说明、章节名、表头、建议动作、质检区是否全部中文
- 允许保留原文的部分仅限：
  - 用户名
  - caption 原文
  - 原始评论原文
  - URL
  - 文件名
- 若出现 `Structure Logic`、`Working Context`、`Yes/No` 之类产品层英文，判为未通过

3. 编码与脏数据
- 不能出现乱码，如 `锛`、`鎬`、`â€™`、`�`
- 不能出现明显本地绝对路径泄漏
- 表格单元格换行要可读，不能大段挤在一行

4. DOCX 视觉层
- 封面、章节页是否有明显卡片感
- 每章是否能清楚看到：章节定位、内容量、表格状态、证据状态
- 长表是否仍可读，没有窄列把长文本挤坏

5. XLSX 可用性
- 总览、章节概览、章节导航是否都存在
- 回链是否正常
- 重点宽表是否分配了正确列宽
- 简单列表页不能仍是旧式平均分列

## 分场景检查

### Scene 01 爆款采集
- 主表是否显式露出评分字段
- 是否能直接看出：
  - 值得研究原因
  - 适合什么品类复用
  - commerce / shopping 信号
  - Scene 03 shortlist 交接价值
- XLSX 主表优先级要高于 Markdown 叙述

### Scene 04 单视频拆解
- 是否有标准时间轴表：
  - 时间段
  - 场景类型
  - 画面内容
  - 口播 / 屏幕文案
- 是否有 BGM / 感官层
- 是否有爆点三分法
- 无口播场景的逻辑是否仍能成立

### Scene 05 反推提示词 / Brief
- 是否清楚分为：
  - 反推原始 Brief
  - 生成器可用结构
  - 产品适配 Brief
- 是否能直接给生成后端 handoff
- 低置信度字段是否有显式标记

### Scene 08 评论挖掘 / 人群画像
- 是否真的偏购买评论，而不是公告 / 平台反应
- 是否能输出：
  - 购买触发因素
  - 好评关键词
  - 差评痛点
  - 价格带差异
- 是否保留来源商品标签
- 是否能从多商品汇总回到品类级建议

### Scene 17 创作者公式提炼
- 是否有账号速览层
- 是否有高互动 vs 低互动对比
- 是否有 hook 公式和脚本节奏模板
- 是否能把创作者专属优势与可迁移公式分开

### Scene 18 竞品账号周报
- 是否体现多账号横向对比，而不是单账号流水账
- 是否能看出本周策略变化
- 是否有评论侧信任 / 反对 / 疑虑信号
- 周报口吻是否更像运营报告而不是 JSON 展示

### Scene 19 自家账号复盘优化
- 是否清楚区分高表现 / 低表现
- 是否能直接得出“多做什么 / 少做什么”
- 是否带下一轮测试建议
- 是否把评论侧摩擦和内容表现联系起来

## 本轮重点观察记录

- Scene 01：重点看评分字段是否足够前置
- Scene 04 / 05 / 17：重点看正文里是否仍残留少量英文模板句
- Scene 08：重点看新 fixture 是否把输出拉向购买型洞察
- Scene 18 / 19：重点看 comment signal 是否足够强，避免只剩周报框架

## 通过标准

- 中文产品面完整
- 无乱码
- 无明显本地路径泄漏
- DOCX 有平台项目卡感
- XLSX 主表可直接给运营看
- 原始证据保真，但结构层不再英文泄漏
