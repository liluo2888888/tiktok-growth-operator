# Scene 19: Self-Account Retro And Optimization

## Use When

- the user wants to review their own account performance and decide the next content cycle
- the output should become an operating plan, not only a retrospective summary

## Minimum Inputs

- a list of recent posts with some performance signal

## Ideal Inputs

- 2 or more recent posting windows when available
- titles
- publish times
- views
- likes
- comments
- saves or shares
- content type labels
- optional conversion or ROI context

## Workflow

1. cluster posts by content mode
2. compare high-performing and low-performing groups
3. identify the traits that really separate winners from losers
4. distinguish one-week observations from multi-week repeated patterns
5. write do-more / do-less / stop rules
6. produce the next-cycle test plan

## Output Contract

- high-vs-low performance grouping
- performance pattern summary
- winning traits
- losing traits
- do-more / do-less / stop rules
- ROI or conversion note when available
- next-cycle test plan

## Direct Prompt

```text
按场景 19 执行：复盘我的账号内容并给出下一轮优化方案。
不要按发布时间顺序流水账复盘，要先按内容模式聚类。

然后明确回答：
1. 高表现内容模式是什么
2. 低表现内容模式是什么
3. 两者差异到底在哪
4. 哪些内容应该多做
5. 哪些内容应该少做
6. 哪些内容应该停止
7. 下一轮具体要测什么

如果有转化或 ROI 线索，也要尽量把内容表现和增长目标挂起来。
如果只有 1 个时间窗口的数据，要把结论写成“本轮观察”而不是长期定律。
```

## Fallback

If performance data is incomplete, keep the retro qualitative but explicitly mark which conclusions are still weak.
